# PRD 2: Main Project, Family Admin Agent (Alexa+ Track)

**Track:** Alexa+ | **Build time:** 10 days | **Builder:** solo | **Needs:** no paid cloud, no card, runs on an 8 GB laptop

## 1. What is it? (simple)

An Alexa+ helper that remembers a family's paperwork and deadlines and helps parents and grandparents find **government schemes they may qualify for**. You build the *toolbox* (an MCP server). Alexa+ (or any MCP-capable AI) is the *brain* that decides when to use it.

**Words you need:**

- **MCP server:** a program that offers "tools" an AI can call.
- **Tool:** one action, such as `add_document`.
- **Streamable HTTP:** the web-based way the AI talks to your server (required by the rules).
- **Agent Skill:** a written playbook that tells an AI how to do a multi-step job well.
- **MCP Apps:** lets a tool return a small visual card (for example a dashboard) instead of only text.

## 2. Problem

One family member quietly manages everyone's paperwork. Documents expire unnoticed, deadlines are missed, and older relatives never learn which benefits they qualify for. Elderly people struggle with apps but can talk.

## 3. Why it can score well

The rules call "single-turn Q&A" and "basic MCP wrapper" obvious. They call these creative: **agentic workflows**, **state kept across sessions**, **media cards**, **MCP Apps** and **Agent Skills**. Our design uses all of them:

| Rule's "creative" example | Our feature |
| --- | --- |
| State across sessions | SQLite remembers the family between conversations |
| Agentic multi-step workflow | `plan_scheme_application`: checks eligibility, builds the checklist and creates dated tasks in one go |
| Agent Skill | `SKILL.md` playbook for family-paperwork help |
| MCP Apps / cards | Family dashboard card (stretch goal) |

## 4. Users

- **Aman (24):** family admin, wants one place for everything
- **Grandma (70):** wants to just ask by voice
- **Parents (50s):** want to learn about benefits and deadlines early

## 5. Scope

**Must have (MVP):**

1. Family members, documents (type + expiry only), tasks
2. Expiry finder and upcoming-deadline list
3. Scheme eligibility from `schemes.json` (3 to 5 real schemes, each with an official source link)
4. Document checklist per scheme
5. `plan_scheme_application` (multi-step)
6. `family_brief` (one spoken-style summary)
7. Simulated Alexa+ chat page
8. Tests + README + MIT license

**Stretch:** Agent Skill file, MCP Apps dashboard card. **Not doing:** storing ID numbers, filing forms, legal advice, any paid service.

## 6. Tools (the toolbox)

| Tool | Does | Returns |
| --- | --- | --- |
| `add_family_member` | saves person (name, relation, birth year, status) | confirmation |
| `list_family_members` | everyone | list |
| `add_document` | doc type, owner, expiry | confirmation |
| `get_expiring_documents` | within N days | list by urgency |
| `add_task` / `list_upcoming_tasks` | deadlines | confirmation / list |
| `check_scheme_eligibility` | matches a person to schemes | schemes + reason ("age >= 60") |
| `get_scheme_checklist` | documents needed | checklist |
| `plan_scheme_application` | eligibility + checklist + tasks | plan summary |
| `family_brief` | everything urgent | short text |

**Design rules:** clear tool descriptions, short plain answers (they may be read aloud), friendly errors, "may be eligible" wording only.

## 7. Architecture

```
 User (voice/text)
       |
 Alexa+  or  Simulated Alexa+ chat page
       |   MCP over Streamable HTTP
       v
 Family Admin MCP Server (Python, FastMCP)
   tools -> logic (dates, rules, summary)
       |                     |
    SQLite              schemes.json
```

**The simulator's "brain" (it needs one to pick tools):**

1. **Default:** a simple intent router in code (keywords to tool calls). Always works, zero cost.
2. **Better demo:** connect an MCP-capable agent (for example Kiro CLI) to the same server, so a real AI chooses the tools.
3. **Optional:** a small local model via Ollama, only if your RAM allows.

## 8. Tech stack

| Layer | Choice | Why |
| --- | --- | --- |
| Language | Python 3.11+ | you already know FastAPI-style Python |
| MCP | official MCP Python SDK (FastMCP) | Streamable HTTP built in |
| Storage | SQLite | one file, tiny |
| Rules | `schemes.json` | readable and easy to extend |
| Test tools | MCP Inspector, pytest | prove it works |
| Simulator | single HTML + JS page | light |

## 9. Safety and privacy

- Store "passport, expires 2027-03-01", never the number
- Demo uses **fake family data**
- Access token + Origin-header check on the server
- Disclaimer: guidance only, verify on the official site
- No government logos or third-party branding in the video
