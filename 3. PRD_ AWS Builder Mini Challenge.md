# PRD 3: AWS Builder Mini Challenge (add-on to the main project)

**Important:** this is **not a separate project**. The rules say mini challenges build on your primary track submission. You build the Family Admin Agent as usual and use AWS tooling **while building it**, with proof.

## 1. What the rules say

- Eligible: any primary-track project that incorporates AWS services (Bedrock, AgentCore, Strands SDK, Kiro Crew, SageMaker, and so on) **with documented integrations**.
- **Kiro Crew qualifies on its own** as a development tool used during the hackathon. You do not also need to call a runtime AWS service.
- Required field: describe which AWS services you used and how, inside your **Product Feedback** answer.
- Judges' examples: *obvious* = a single Bedrock call or S3 for storage. *Creative* = multi-service pipelines, **agentic architecture with Kiro for the development workflow**, agent orchestration patterns.

## 2. Our approach: Kiro Crew as the build team

**Kiro Crew** is AWS's open-source (Apache 2.0) workspace that runs on your own machine on top of Kiro CLI. It keeps context between sessions and can run several agents in parallel. It does not need an AWS account. Its agents need Kiro for model access, and the free tier gives 50 credits a month with no card (as far as I could verify).

**Why this fits you:** no card, no cloud bills, and you learn spec-driven development and multi-agent workflows.

## 3. What we will do with it (3 uses, each leaves evidence)

| # | Use | Evidence to keep |
| --- | --- | --- |
| 1 | **Spec-driven development:** write requirements, design and task lists with Kiro before coding the tools | `.kiro/` folder (specs + steering files) committed to the repo |

Optional, only if credits allow: use Kiro CLI as the MCP client that calls your server, so a real AI picks your tools in the demo.

## 4. Deliverables

2. Committed `.kiro/` specs and steering files
3. The AWS section of Product Feedback (template below)

## 5. Acceptance criteria

- At least **2 of the 3 uses** completed with evidence in the repo
- Every claim in the submission matches something visible in the repo or video (do not claim Bedrock or AgentCore if you did not use them)
- You can explain in plain words what Crew did and what you reviewed yourself

## 6. Product Feedback template

- **Tools used and for what:** Kiro CLI / Kiro Crew: spec-driven development, parallel test and doc writing, security review
- **What worked well:** (setup, docs, speed, memory)
- **What needs work:** (errors, credit usage, anything unclear)
- **Onboarding (zero to hello world):** (time taken, blockers)
- **Would you build with it again?** Yes/No + reason

## 7. Risks and fixes

| Risk | Fix |
| --- | --- |
| 50 free credits run out | Use Crew for the highest-value tasks only (tests, security review); do everything else by hand. Check whether the Kiro Students offer is open to your college at kiro.dev/students |
| Crew is heavy for an 8 GB laptop | Close other apps; run one session at a time; if it fails, use Kiro CLI alone and document it honestly |
| Crew's setup details have changed | Follow the official GitHub README (github.com/kirodotdev/KiroCrew), since I could not verify exact commands |
| Judges see only "I used a tool" | Evidence in repo + a short clip in the video |
